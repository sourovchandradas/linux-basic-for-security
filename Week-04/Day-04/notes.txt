1. INTRODUCTION TO LINUX SERVICES
--------------------------------------------------------------------------------------------------------------------------------------
* What is a Service?
    -> A daemon or application that runs continuously in the system background.
    -> Remains in a passive listening state until a client request or user trigger occurs.
    -> Essential for system administration, hosting infrastructure, and remote management.

* Core Services Analyzed in Penetration Testing:
    1. Apache HTTP Server : World's most popular web server. Used for hosting content, payloads, and phishing pages.
    2. OpenSSH            : Secure Shell daemon providing encrypted remote shell access (replaces legacy Telnet).
    3. MySQL / MariaDB    : Relational Database Management System (RDBMS) storing web applications and backend user data.
    4. PostgreSQL         : Advanced open-source RDBMS often used in enterprise environments and for storing attack metrics.

* Chapter Core Objectives:
    -> Setting up and customizing an HTTP web server using Apache.
    -> Constructing a remote surveillance tool ("Raspberry Spy Pi") using OpenSSH and camera modules.
    -> Accessing, managing, and extracting data from backend databases (MySQL/MariaDB/PostgreSQL).


2. SERVICE MANAGEMENT MECHANICS (`systemctl` vs. `service`)
--------------------------------------------------------------------------------------------------------------------------------------
* Service Control Frameworks:
    -> Legacy Framework (`service`)  : SysVinit style management. Uses syntax: `service <servicename> <action>`
    -> Modern Framework (`systemctl`): Systemd init system. Uses syntax: `sudo systemctl <action> <servicename>`

* Command Reference Matrix:

    Action            | Legacy Syntax (`service`)      | Modern Syntax (`systemctl`)
    ------------------+--------------------------------+----------------------------------------
    Start Service     | service apache2 start          | sudo systemctl start apache2
    Stop Service      | service apache2 stop           | sudo systemctl stop apache2
    Restart Service   | service apache2 restart        | sudo systemctl restart apache2
    Check Status      | service apache2 status         | sudo systemctl status apache2
    Enable on Boot    | update-rc.d apache2 enable     | sudo systemctl enable apache2

📌 Critical Architectural Concept:
    -> When you modify a service's plain-text configuration file (e.g., `/etc/apache2/apache2.conf`), the changes exist ONLY on disk.
    -> You MUST restart or reload the service (`restart` / `reload`) to force the daemon to reread the file into active RAM memory.


3. CREATING AN HTTP WEB SERVER WITH APACHE
--------------------------------------------------------------------------------------------------------------------------------------
* Industry Footprint & Importance:
    -> Powers ~55% of global web servers.
    -> Understanding Apache is mandatory for web application assessment, website security, and backend database interaction.

* Offensive Applications (Red Teaming / Ethical Hacking):
    - Payload Delivery  : Hosting malicious executables or scripts to deliver via Cross-Site Scripting (XSS).
    - Phishing Clones   : Mirroring authentic web portals and serving them locally.
    - Traffic Redirection: Combining cloned sites with DNS Spoofing / Poisoning to capture user credentials.

* Web Application Stacks:
    - LAMP Stack (Linux)   : Linux OS + Apache Web Server + MySQL Database + PHP/Python Scripting.
    - WAMP Stack (Windows) : Windows OS + Apache Web Server + MySQL Database + PHP/Python Scripting.

* Installation, Execution, and Verification Workflow:
    1. Installation       : `sudo apt install apache2` (or `apt-get install apache2`)
    2. Launch Daemon      : `sudo systemctl start apache2`
    3. Verification       : Open browser and navigate to `http://localhost/` or `http://127.0.0.1/`
                            (Default landing page displays: "Apache2 Debian Default Page: It works").

* Web Content Customization & File Architecture:
    - Default Web Root Path : `/var/www/html/`
    - Main Entry File Path  : `/var/www/html/index.html`
    - Editing Command       : `sudo mousepad /var/www/html/index.html` (or `nano`, `leafpad`)

* Custom HTML Sample Injection:
    ```html
    <!DOCTYPE html>
    <html>
      <body>
        <h1>Hackers-Arise Is the Best!</h1>
        <p>If you want to learn hacking, Hackers-Arise.com is the best place to learn hacking!</p>
      </body>
    </html>
    ```
    -> Action : Overwrite `/var/www/html/index.html`, save, and refresh `http://localhost/` to render custom web content.


4. REMOTE ACCESS & SURVEILLANCE VIA OPENSSH ("RASPBERRY SPY PI")
--------------------------------------------------------------------------------------------------------------------------------------
* SSH (Secure Shell) Protocol Mechanics:
    - Runs on Default Port 22.
    - Encrypted replacement for Telnet, RLOGIN, and RSH.
    - Security Features : Access Control Lists (ACLs), public/private key or encrypted password authentication, end-to-end traffic encryption.
    - Usage : Admins manage remote servers; attackers maintain persistent access to compromised targets.
    - Local Kali Start  : `sudo systemctl start ssh`

* Raspberry Spy Pi Project Overview:
    - Concept   : Transform a credit-card-sized computer into a covert, remote surveillance platform.
    - Hardware  : Raspberry Pi board (~$50) + Raspberry Pi Camera Module (~$15).
    - OS        : Raspberry Pi OS (formerly Raspbian) – Debian port optimized for ARM CPUs.
    - Legacy Default Credentials : Username: `pi` | Password: `raspberry`

* Step-by-Step Hardware & Network Deployment:
    1. Enable SSH Service on Pi :
       - GUI Method : Preferences -> Raspberry Pi Configuration -> Interfaces -> Enable SSH -> Click OK.
       - CLI Method : `sudo systemctl start ssh`
    2. Attach Camera Module :
       - SHUT DOWN the Raspberry Pi completely.
       - Insert ribbon cable into the dedicated camera interface port.
       - ⚠️ CRITICAL WARNING: The camera module is fragile. Never allow camera circuitry or ribbon leads to contact GPIO pins (will cause a fatal short circuit).
       - Power ON the Raspberry Pi.
    3. Network Enumeration :
       - Connect Pi to local network via Ethernet or Wi-Fi.
       - Run `ifconfig` in Pi terminal to obtain private IP address (e.g., `192.168.1.101`).
    4. Establish Remote Control via SSH (from Kali Linux) :
       - Command : `ssh pi@192.168.1.101`
       - Enter default password (`raspberry`) when prompted.

* Camera Configuration & Remote Surveillance Execution:
    1. Launch Configuration Utility :
       - Command : `sudo raspi-config`
       - Navigation : Select Option 6 (Interface Options / Enable Camera) -> Enable -> Finish.
       - Reboot System when prompted.
    2. Remote Image Capture Commands :
       - Re-establish SSH connection post-reboot (`ssh pi@192.168.1.101`).
       - Legacy Raspbian Command (`raspistill`) :
         `raspistill -v -o firstpicture.jpg`
         * `-v` = Verbose diagnostic output
         * `-o` = Output path/filename
       - Modern Raspberry Pi OS Command (`rpicam-still`) :
         `rpicam-still --output firstpicture.jpg`
    3. Verification :
       - Run `ls -l` in the remote terminal to verify that `firstpicture.jpg` was written to disk.
