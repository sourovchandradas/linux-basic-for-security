1. Scheduling Recurring Tasks with Cron
--------------------------------------------------------------------------------------------------------------------------------------
* Crontab Field Structure (System-Wide: `/etc/crontab`):
  
  FIELD | ELEMENT      | RANGE       | DESCRIPTION
  ------+--------------+-------------+-----------------------------------------------------------
    1   | Minute       | 0–59        | Exact minute of the hour.
    2   | Hour         | 0–23        | 24-hour notation (e.g., 13 = 1 PM, 23 = 11 PM).
    3   | Day of Month | 1–31        | Day of the calendar month.
    4   | Month        | 1–12        | Month of the year (1 = Jan, 12 = Dec).
    5   | Day of Week  | 0–7         | Day of the week (0 and 7 both represent Sunday).
    6   | User         | account     | User context executing the task (e.g., root, backup).
    7   | Command      | path/binary | Absolute path to execution binary or script.

* Syntax Operators:
    - `*` (Wildcard) : Matches all valid field values (every minute, day, month, etc.).
    - `-` (Range)    : Inclusive continuous interval (e.g., `1-5` = Monday–Friday).
    - `,` (List)     : Non-contiguous discrete values (e.g., `15,30` = 15th and 30th days).

* Cron Timing Shortcuts:
  
  SHORTCUT     | EQUIVALENT  | DESCRIPTION
  -------------+-------------+----------------------------------------------------------------
  @reboot      | Startup     | Runs once immediately upon system boot.
  @yearly      | 0 0 1 1 *   | Runs once annually on Jan 1st at 12:00 AM.
  @monthly     | 0 0 1 * *   | Runs once monthly on the 1st at 12:00 AM.
  @weekly      | 0 0 * * 0   | Runs once weekly on Sunday at 12:00 AM.
  @daily       | 0 0 * * *   | Runs once daily at 12:00 AM (@midnight).
  @noon        | 0 12 * * *  | Runs once daily at 12:00 PM.


2. Execution Syntax & Practical Examples
--------------------------------------------------------------------------------------------------------------------------------------
* Weekday Execution (Mon–Fri at 2:30 AM):
  `30 2 * * 1-5 root /root/myscanningscript.sh`

* Mid-Month Backup (15th & 30th at 2:00 AM):
  `00 2 15,30 * * backup /bin/systembackup.sh`

* Summer Weekend Scanning (June–August, Sat/Sun at 2:00 AM):
  `00 2 * 6-8 0,6 user /usr/share/MySQLscanner.sh`

* Daily Midnight Maintenance (Using Shortcut):
  `@midnight user /usr/share/MySQLscanner.sh`


3. Boot Automation & Initialization Control
--------------------------------------------------------------------------------------------------------------------------------------
* Standard Runlevels:
  
  LEVEL | OPERATIONAL TARGET STATE
  ------+------------------------------------------------------------------------------------
    0   | Halt (Shuts down OS)
    1   | Single-User / Recovery Mode (Minimal baseline without networking)
   2–5  | Multi-User Modes (Standard operational targets with networking)
    6   | Reboot (Restarts system)

* Service Boot Persistence (`update-rc.d`):
    - Register default runlevel symlinks:
      `kali > update-rc.d postgresql defaults`
    - Verify running daemon process status:
      `kali > ps aux | grep postgresql`


4. Quick Command Summary / Cheat Sheet
--------------------------------------------------------------------------------------------------------------------------------------
* Edit Current User Crontab          : crontab -e
* Edit System Crontab Directly       : sudo nano /etc/crontab
* Enable Service Boot Auto-Start     : sudo update-rc.d <service_name> defaults
* Launch TUI Startup Configurator    : rcconf
* Search Active Service Processes    : ps aux | grep <process_name>
