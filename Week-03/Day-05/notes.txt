2. A Crash Course in Bash & Shell Basics
------------------------------------------------------------------------
* What is a Shell?
  -> An interactive interface between the user and the Linux kernel.
  -> Executes programs, manipulates files, and invokes system commands directly without GUI overhead.
* Types of Shells in Linux:
  -> Korn shell (ksh)
  -> Z shell (zsh)
  -> C shell (csh)
  -> Bourne-again shell (bash) -> The default and most widely adopted shell across distributions.
* Why Bash?
  -> Pre-installed on virtually all UNIX/Linux environments (including Kali Linux and macOS).
  -> Directly executes binary applications, system tools, and native built-in commands.
* Key Commands Introduced:
  -> echo : Prints messages, strings, or variable values directly to the terminal display.
  -> read : Accepts user keyboard input and stores it into a designated variable.
* Text Editors for Scripting:
  -> Plain text editors are mandatory (no rich-text formatting). Examples include vi, vim, nano, gedit, and leafpad.


3. Writing Your First Script: "Hello, Hackers-Arise!"
------------------------------------------------------------------------
* Purpose:
  -> Understand basic script creation, execution permissions, and terminal text output.

Script Code (File: HelloHackersArise):
#!/bin/bash
# This is my first bash script. Wish me luck.
echo "Hello, Hackers-Arise!"

Key Structural Concepts:
* Shebang (#!):
  -> Always placed at the very first line (`#!/bin/bash`).
  -> Informs the Linux kernel which interpreter should execute the file.
* Comments (#):
  -> Lines starting with `#` are ignored during execution.
  -> Used for inline documentation to explain logic to developers and users.

Command (Granting Execution Permission):
kali > chmod +x HelloHackersArise

Command (Executing the Script):
kali > ./HelloHackersArise

Output/Explanation:
Hello, Hackers-Arise!

* Why Use `./`?:
  -> Explicitly targets execution from the current directory.
  -> Prevents executing same-named executables located in the system PATH directory.


4. Adding Functionality with Variables and User Input
------------------------------------------------------------------------
* What is a Variable?
  -> A named storage location in system memory that holds values (strings or numbers) that can change during execution.
* Purpose:
  -> Introduces interactivity and dynamic data handling to make scripts flexible across different environments.

Script Code (File: WelcomeScript.sh):
#!/bin/bash
# This script prompts for user input, stores it in variables, and outputs dynamic text.

echo "What is your name?"
read name

echo "What chapter are you on in Linux Basics for Hackers?"
read chapter

echo "Welcome $name to Chapter $chapter of Linux Basics for Hackers!"

Command (Permission & Execution):
kali > chmod +x WelcomeScript.sh
kali > ./WelcomeScript.sh

Execution Output:
What is your name?
OccupytheWeb
What chapter are you on in Linux Basics for Hackers?
8
Welcome OccupytheWeb to Chapter 8 of Linux Basics for Hackers!

Command & Syntax Breakdown:
* read <var_name> : Intercepts standard input and binds the value to the variable name.
* $ Variable Access: Preceding a variable name with `$` reads and substitutes its actual content.
* File Extension: Saving files with `.sh` is standard convention to clearly signify a shell script.

⚠️ Rules to remember:
  -> Assign variables without `$`, but ALWAYS dereference/access their values using `$`.
  -> Executing a script without running `chmod +x` will raise a "Permission denied" error.

🔑 One-liner:
Shebang (`#!/bin/bash`) sets the runtime engine, `read` captures user input, `$` extracts variable data, and `./` ensures local path execution.
