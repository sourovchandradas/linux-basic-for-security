2. A Crash Course in Bash & Shell Basics
--------------------------------------------------------------------------------------------------------------------------------------
* What is a Shell?
    -> An interactive interface between the user and the operating system.
    -> Executes programs, manipulates files, and invokes system commands directly without GUI overhead.
* Types of Shells in Linux:
    -> Korn shell (ksh)
    -> Z shell (zsh)
    -> C shell (csh)
    -> Bourne-again shell (bash) -> The default and most widely adopted shell across distributions.
* Why Bash?
    -> Pre-installed on virtually all UNIX/Linux environments (including Kali Linux and macOS).
    -> Directly executes binary applications, system tools, and native built-in commands.
* Key Commands Introduced:
    -> echo : Prints messages, strings, or variable values directly to the terminal display.
    -> read : Accepts user keyboard input and stores it into a designated variable.
* Text Editors for Scripting:
    -> Plain text editors are mandatory (no rich-text formatting). Examples include vi, vim, nano, gedit, and leafpad.

📌 Summary
    -> Shell = interface between user & OS
    -> Types → ksh, zsh, csh, bash
    -> Bash → most widely used, built‑in commands
    -> New commands → echo, read
    -> Editors → vi, vim, emacs, gedit, kate

✅ Exam Key Points
    -> Define shell + advantage
    -> Name 4 shells
    -> Why bash chosen?
    -> New commands → echo, read
    -> Popular editors → vi, vim, emacs


3. Writing Your First Script: "Hello, Hackers-Arise!"
--------------------------------------------------------------------------------------------------------------------------------------
* Purpose:
    -> Understand basic script creation, execution permissions, and terminal text output.

Script Code (File: HelloHackersArise):
 #!/bin/bash
 # This is my first bash script. Wish me luck.
 echo "Hello, Hackers-Arise!"

Key Structural Concepts:
* Shebang (#!):
    -> Always placed at the very first line (`#!/bin/bash`).
    -> Informs the Linux kernel which interpreter should execute the file.
* Comments (#):
    -> Lines starting with `#` are ignored during execution.
    -> Used for inline documentation to explain logic to developers and users.

Command (Granting Execution Permission):
 kali > chmod +x HelloHackersArise

Command (Executing the Script):
 kali > ./HelloHackersArise

Output/Explanation:
 Hello, Hackers-Arise!

📌 Summary
    -> Purpose → print message
    -> Shebang → #!/bin/bash
    -> Command → echo
    -> Comments → start with #
    -> Save + run → chmod +x, ./filename

✅ Exam Key Points
    -> Purpose of shebang
    -> Interpreter → Bash
    -> Command for text → echo
    -> Importance of comments


4. Setting Execute Permissions
--------------------------------------------------------------------------------------------------------------------------------------
* Default Permission Behavior:
    -> By default, newly created bash script files lack execute permissions, even for the owner or creator.
    -> Default permission representation: `-rw-r--r--` (644), meaning read and write for the owner, and read-only for group and
       others.

Command (Checking Default File Permissions):
 kali > ls -l

Output:
 -rw-r--r-- 1 root root 90 Oct 22 14:32 HelloHackersArise

Explanation:
    -> Owner has `rw-` (read, write), but NO `x` (execute) permission.

* Granting Execute Permissions:
    -> Must modify file permissions using `chmod` to make the script executable.
    -> Using `chmod 755` grants read, write, and execute (`rwx`) to the owner, and read and execute (`r-x`) to group and others.
    -> Alternatively, `chmod +x` adds execute permission to the file.

Command (Granting Execution Rights):
 kali > chmod 755 HelloHackersArise

Command (Verifying Modified Permissions):
 kali > ls -l

Output:
-rwxr-xr-x 1 root root 90 Oct 22 14:32 HelloHackersArise

Explanation:
    -> The file now displays `-rwxr-xr-x`, indicating full execution permissions.
    -> In the Linux terminal, executable files are highlighted in GREEN text as a visual indicator.

📌 Summary
    -> Default new script permission → -rw-r--r-- (644)
    -> Owner → read + write, no execute
    -> Must use chmod to add execute
    -> chmod 755 → owner: rwx, group: r-x, others: r-x
    -> chmod +x → adds execute permission
    -> Check with ls -l → executable files show x and green highlight

✅ Exam Key Points
    -> Default permission → 644 (-rw-r--r--)
    -> Why no execute by default? → security
    -> Command to add execute → chmod 755 or chmod +x
    -> How to check? → ls -l
    -> Owner permissions with 755 → rwx


5. Running HelloHackersArise
--------------------------------------------------------------------------------------------------------------------------------------
Command (Executing the Script):
 kali > ./HelloHackersArise

Output:
 Hello, Hackers-Arise!

* Why Use `./`?:
    -> Explicitly targets execution from the current working directory.
    -> Prevents executing same-named executables located elsewhere in the system PATH directory.

📌 Summary
    -> Run → ./HelloHackersArise
    -> ./ → current directory execution
    -> Output → Hello, Hackers-Arise!
    -> Best practice → avoids duplicates

✅ Exam Key Points
    -> Why ./ ? → current directory
    -> Output → Hello, Hackers-Arise!
    -> Good practice → avoids wrong file
    -> Successful run → script correct

6. Adding Functionality with Variables and User Input
--------------------------------------------------------------------------------------------------------------------------------------
* What is variables?
    -> A variable is an area of storage that can hold something in memory. That “something” might be some letters or words (strings)
       or numbers. It’s known as a variable because the values held within it are changeable; this is an extremely useful feature for
       adding functionality to a script.
* Purpose:
    -> Introduces interactivity and dynamic data handling to make scripts flexible across different environments.

Script Code (File: WelcomeScript.sh):
 #!/bin/bash
 # This script prompts for user input, stores it in variables, and outputs dynamic text.

 echo "What is your name?"
 read name

 echo "What chapter are you on in Linux Basics for Hackers?"
 read chapter

 echo "Welcome $name to Chapter $chapter of Linux Basics for Hackers!"

Command (Permission & Execution):
 kali > chmod +x WelcomeScript.sh
 kali > ./WelcomeScript.sh

Execution Output:
 What is your name?
 OccupytheWeb
 What chapter are you on in Linux Basics for Hackers?
 8
 Welcome OccupytheWeb to Chapter 8 of Linux Basics for Hackers!

Command & Syntax Breakdown:
* read <var_name>    : Intercepts standard input and binds the value to the variable name.
* $ Variable Access  : Preceding a variable name with `$` reads and substitutes its actual content.
* File Extension     : Saving files with `.sh` is standard convention to clearly signify a shell script.

⚠️ Rules to remember:
    -> Assign variables without `$`, but ALWAYS dereference/access their values using `$`.
    -> Executing a script without running `chmod +x` will raise a "Permission denied" error.

🔑 One-liner:
     -> Shebang (`#!/bin/bash`) sets the runtime engine, `read` captures user input, `$` extracts variable data, and `./` ensures
        local  path  execution.
