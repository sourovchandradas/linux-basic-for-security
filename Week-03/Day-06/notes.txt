1. Introduction to Port Scanning & Nmap Basics
--------------------------------------------------------------------------------------------------------------------------------------
* What is Port Scanning?
    -> Probing a target system connected to a network to discover open ports.
    -> Open ports reveal running services, helping administrators or attackers evaluate target security.

* What is Nmap?
    -> Network Mapper: An essential, pre-installed network scanner on Kali Linux.
    -> Used to discover hosts, open ports, and network services.

* Fundamental Nmap Syntax:
    kali > nmap -sT <Target_IP> -p <Port_Number>

Explanation:
    -> -sT : Performs a TCP Connect Scan (the standard, full 3-way handshake scan).
    -> -p  : Specifies the port number to target (e.g., -p 3306 for MySQL, -p 5505 for Aloha POS).

📌 Summary
    -> Port scanning reveals active network services.
    -> Syntax → nmap -sT <IP> -p <Port>.
    -> Key flags → -sT (TCP connect), -p (port specification).

✅ Exam Key Points
    -> Purpose of Nmap.
    -> Function of the -sT switch.
    -> How to target a specific port using -p.

3. Writing a Simple DNS Local Area Network Scanner
--------------------------------------------------------------------------------------------------------------------------------------
* Scenario & Goal:
    -> Scan a local subnet (e.g., 10.0.2.0/24) for default DNS  instances (Port 53).

* Script Implementation (dnsServer.sh):

    #!/bin/bash
    # This script is designed to find hosts with DNS installed
    nmap -sT 10.0.2.0/24 -p 53 >/dev/null -oG dnsServer
    cat dnsServer | grep open > dnsServer2
    cat dnsServer2

* Execution Steps:
    kali > chmod 755 dnsServer.sh
    kali > ./dnsServer.sh
    Host: 192.168.181.69 () Ports: 3306/open/tcp//mysql///

Explanation of Key Commands & Redirections:
    -> >/dev/null : Discards standard output so terminal screen output remains clean.
    -> -oG        : Outputs Nmap scan results in "Grepable" format (easy to parse line-by-line).
    -> grep open  : Filters lines to display only active hosts with the port status marked as open.

📌 Summary
    -> Command → nmap -sT <Subnet> -p 3306 >/dev/null -oG dnsServer.
    -> Output filtering → grep open extracts active targets.
    -> Perms → chmod 755 to grant execution rights.

✅ Exam Key Points
    -> Purpose of /dev/null redirection.
    -> Purpose of -oG switch in Nmap.
    -> How to pipe Nmap output to grep.


4. Building an Advanced Dynamic Port Scanner
--------------------------------------------------------------------------------------------------------------------------------------
* Why Upgrade?
    -> Hardcoded IP subnets and ports require editing the script file every time.
    -> Using variables and user prompts (read) allows dynamic input for any subnet range and port.

* Script Implementation (dnsScript):

    #!/bin/bash
    echo "Enter the starting IP address : "
    read FirstIP
    echo "Enter the last octet of the last IP address : "
    read LastOctetIP
    echo "Enter the port number you want to scan for : "
    read port
    nmap -sT $FirstIP-$LastOctetIP -p $port >/dev/null -oG dnsScript
    cat dnsScript | grep open > dnsScript
    cat dnsScript

* Execution Output Sample:
    kali > ./dnsScript
    Enter the starting IP address : 
    10.0.2.0
    Enter the last octet of the last address : 
    254
    Enter the port number you want to scan for : 
    53
    Host: 192.168.181.254 () Ports: 3306/open/tcp//mysql///

Explanation:
    -> FirstIP, LastOctetIP, and port store interactive user responses.
    -> Range Syntax: $FirstIP-$LastOctetIP expands to 10.0.2.1-254.
    -> Allows scanning custom ports and networks without altering source code.

📌 Summary
    -> Variable capture → read variable_name.
    -> Range scan syntax → $FirstIP-$LastOctetIP.
    -> Dynamic flexibility → Prompts user for target range and port.

✅ Exam Key Points
    -> Syntax for accepting user input (read).
    -> Referencing dynamic variables in commands ($FirstIP, $port).

6. Important Rules and Best Practices
--------------------------------------------------------------------------------------------------------------------------------------
⚠️ Key Rules to Remember:

1. Nmap Redirection Efficiency:
    -> Redirecting raw scan output to /dev/null keeps terminal execution clean during automation.
2. Grepable Format (-oG):
    -> Always use -oG when outputting Nmap scans intended for parsing via grep or text utils.
3. Variable Expansion in Range Scans:
    -> Ensure correct concatenation formatting when defining IP ranges: $FirstIP-$LastOctetIP.
4. Execution Permissions:
    -> Always assign execute privileges (chmod 755 <script>.sh) before trying to run ./<script>.sh.
5. Error Handling in Pipelines:
    -> Clean temporary grep output files or overwrite them using single redirect > to avoid stale data.

* One-liner to Remember:
-> Nmap gathers network ports, -oG structures the data, grep extracts open targets, and read captures user parameters.

📌 Summary
    -> Nmap -oG → structured grepable format.
    -> >/dev/null → discard unnecessary output.
    -> chmod 755 → grant script execution rights.

✅ Exam Key Points
    -> Why -oG is preferred for shell scripting.
    -> How to clean terminal output during execution.
    -> One-liner: Nmap gathers, -oG structures, grep extracts, read captures.
